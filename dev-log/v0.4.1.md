## Results

**Presence.** The runtime keeps `clientId -> {author, cursor, selection, view, at}`
for the open mode, validates a report before recording it, broadcasts a `presence`
event and answers `GET /api/edit/presence` for a late joiner. An entry expires
after 30 s and `leaving: true` removes it at once; nothing is persisted. The page
reports the cursor on pointer movement and the view point on a viewport change,
throttled to 120 ms, and draws a collaborator's selection and cursor with their
author named in the toolbar roster.

**Merging.** The service remains the only writer: it serialises transactions per
session, rebases an absolute intent whose base is behind, and refuses a
content-dependent one with `stale_base`. Two authors writing different cells both
survive; an overlapping write resolves to the later commit; every subscriber
receives the same `version` and `hash`. A page that receives a version it cannot
follow resynchronises through `/api/edit/state`.

**Cross-author undo.** `POST /api/edit/undo` accepts `txId`, so an author can undo
their own transaction. The inverse patch is limited to the cells the transaction is
still the last writer of, so a cell another author wrote later keeps its newer
value. The undo is itself a transaction and reaches both clients as a `patch`
event.

**Bounded memory.** A transaction that leaves the 1000-transaction retained window
is removed from the undo and redo stacks, and its per-cell attribution entries are
deleted with it. The cost is explicit: undo depth equals the window. The model
case fills the window and asserts the bound and the compaction.

**The phase record.** The phase overview, design, milestones, tasks, acceptance and
risks had said `Planned` and "no part of the mode exists in the tree" after M00 was
delivered. They now say `Partially Implemented`, with M00 and M01 implemented and
M02/M03 planned, and the acceptance file carries the judged note for E11–E13.

## Failures

### F50 — the page sent a cursor object where the route expects a pair

The first page presence case failed because the page forwarded the
`screenToWorld` result (`{x, y}`) as `cursor`, and the service's presence
validation accepts only an `[x, y]` pair. The page now stores and sends the pair;
the test then asserted the reported value. Kept because the route and the page had
two representations of the same point, which is the kind of mismatch a typed
boundary would have caught earlier.

### F51 — a throttled report was read before it was sent

The same test then read the recorded presence before the 120 ms coalescing window
elapsed and saw the enter-time report (cursor `null`). The test waits past the
window now. This was a test-timing defect, not a product one, and it is recorded
because it explains why the suite waits on a real timer at that point.

## Deviations from the plan

| Planned | Delivered | Reason |
|---|---|---|
| Unlimited undo depth | Undo depth bounded by the 1000-transaction retained window | The window is what bounds memory; keeping attribution for every transaction ever committed would defeat the compaction EDR-02 asks for. The limit is stated in the interface and the dev-log rather than hidden |
| Presence rendering as a rich overlay | A cursor, a selection outline and a roster of authors | The milestone names presence, not a rendering specification; a roster and the two overlays are enough for a person to see who is editing where |
| A separate collaboration channel | Presence and patches on the existing event stream, a POST for the client's own reports | The event stream already carries every change; a second transport would need its own lifecycle for no new information |
