## Failures, and what they cost

Failures are kept verbatim, as required by
[../docs/AI_DOCUMENTATION_GUIDE.md](../docs/AI_DOCUMENTATION_GUIDE.md) §2.

### F1 — the sandbox could not provision three directories

Creating any file inside `TEMP/`, `docs/` or `data/` failed with
`UnauthorizedAccessException` while the same operation succeeded in a freshly
created directory. Reads worked; rename and delete failed too. Root cause and
evidence: [../evidence/windows-directory-access-label.md](../evidence/windows-directory-access-label.md).
Resolved by removing the three empty directories after verifying they contained
no files, then recreating them from the working session so they inherit the
label and the sandbox's own access entry.

### F2 — uv downloaded a second interpreter to the system volume

The first `uv venv` run was launched before `scripts/env.ps1` could be sourced,
because the machine execution policy blocked the dot-source:

```
. : 无法加载文件 <repo>\scripts\env.ps1。未对文件 ... 进行数字签名。
```

With `UV_PYTHON_INSTALL_DIR` unset, uv installed CPython 3.14.7 under the user
profile on the system volume and created the virtual environment from it.
Resolved by deleting exactly the two 3.14 payload directories that run had
created (each verified to be CPython 3.14 before deletion; the pre-existing
3.12 payloads were left untouched), then recreating the environment with the
contract in force. Cost: 114 MB temporarily written to the system volume.

### F3 — the isolation check itself was broken in four ways

Found by review and by a failing run, not by the check passing:

1. `$home` collides with the read-only automatic variable `$HOME` in
   PowerShell, which is case-insensitive, so the static phase aborted after
   eight checks.
2. Exit code `2` was documented but never emitted, so an incomplete check was
   indistinguishable from a violation.
3. `env.ps1` created directories and set variables before running its guard, so
   a repository hosted on the system volume would have been written to before
   the refusal.
4. Three published variables (`LIFEGAME_ROOT`, `PIP_CONFIG_FILE`,
   `npm_config_tmp`) were not guarded.

All four are fixed; the guard now runs first and refuses without side effects,
`trap` maps an unexpected failure to exit `2`, and the guard list is asserted in
three places (`scripts/env.ps1`, `scripts/verify-temp-isolation.ps1`,
`tests/environment/test_isolation_contract.py`). The environment module records
this in
[../docs/model/environment/testing.md](../docs/model/environment/testing.md).

### F4 — `npm_config_tmp` produced a terminating warning

npm 11 reports `tmp` as an unknown configuration key and writes a warning to
stderr. Under `$ErrorActionPreference = 'Stop'`, PowerShell 5.1 converts a
native stderr line into a terminating error even when it is redirected, so the
whole check exited `2`. Resolved on both sides: `npm_config_tmp` and the
`tmp=` key were removed (Node's temporary directory is already decided by
`TEMP`/`TMP`), and every native invocation now goes through a helper that
collects stdout, drops stderr and records the exit code separately.

### F5 — the pnpm store check passed while verifying nothing

`pnpm config get store-dir` returned the literal string `undefined` for a key
pnpm 12 no longer reads, and `GetFullPath('undefined')` resolves inside the
repository, so the check reported `OK`. The same run showed the real store at a
location outside the repository. Resolved by requiring an absolute path,
rejecting `undefined`/`null`/`true`/`false`/`nan`, reading pnpm's own
`storeDir`/`cacheDir` keys, resolving `pnpm store path`, and moving the store
and cache into the repository through `pnpm-workspace.yaml`.

### F6 — a concurrent build corrupted the tool binary

`docguard.exe` was found at 0 bytes with an empty `.ninja_log`, after a build
triggered from inside the isolation check ran at the same time as another
build. Resolved by removing the build directory and rebuilding cleanly
(15 translation units, 4.66 s). The lesson is recorded in
[../docs/model/documentation/risks.md](../docs/model/documentation/risks.md):
the C++ tool build is not safe to run concurrently, and the gate should not be
invoked from inside another gate.

### F7 — the bootstrap script could not provision a clean checkout

Found by the first cold-clone run, which is the only run that exercises it: on a
clone with no interpreter present, `scripts/bootstrap.ps1` aborted after
0.6 s with

```
uv.exe : error: No interpreter found for Python 3.14 in virtual environments or managed installations
Step failed: install uv-managed CPython 3.14 into .cache/uv-python
```

The probe `uv python find 3.14` writes that message to stderr, and under
`$ErrorActionPreference = 'Stop'` PowerShell 5.1 turns a native stderr line
into a terminating error. Every warm run passed because the probe *succeeds*
there and prints nothing to stderr — so the defect was invisible until the
environment was exercised from nothing.

Resolved by routing every native call in the script through two helpers.
`Invoke-NativeCapture` collects the first stdout line, drops stderr and records
the exit code separately; `Invoke-NativeStream` sends output to the console with
`Out-Host` so the function's return value is the exit code and nothing else.
`Invoke-Step` now requires the step body to return an exit code and raises on a
non-zero value. Verified by the cold-clone run above (522.6 s, exit 0).

### F8 — cache paths were bound to one checkout

Every declared cache location named the primary checkout:

```
cache-dir = "<repo>/.cache/uv"          # uv.toml
cache        = <repo>/.cache/npm        # .npmrc
storeDir     = <repo>/.cache/pnpm-store # pnpm-workspace.yaml
cache-dir    = <repo>/.cache/pip        # scripts/pip.ini
```

A clone or a git worktree therefore wrote its caches **into the original
checkout**, while each copy reported itself isolated. The clone's isolation
check failed on exactly the three pnpm locations.

Resolved by making every declared path checkout-relative, and by removing all
settings from `.npmrc` so that npm's cache location is owned solely by
`scripts/env.ps1` — which computes absolute values for the checkout that is
actually running. The decision is recorded in
[../docs/adr/governance-and-build/0004-cache-locations-are-checkout-relative.md](../docs/adr/governance-and-build/0004-cache-locations-are-checkout-relative.md),
which supersedes the absolute-path clause of ADR 0002 rather than rewriting it.

The isolation check now validates both forms, because one form alone is not
enough: a purely relative declaration can be declared correctly and ignored by
the tool (exactly the F5 failure), and a purely resolved check cannot tell that
the resolved path belongs to a *different* checkout.

### F9 — the version was committed and tagged before the cold-clone check

The first baseline commit and the `v0.1.0` tag were created after every gate
passed on the warm tree. F7 and F8 were found afterwards, by the cold-clone
run, and both are part of delivering this version. The commit was amended and
the tag moved to the corrected revision. The correction is listed in
[../docs/plan/VERSIONS.md](../docs/plan/VERSIONS.md); no other copy of the tag
exists, because the repository has no remote.

The lesson is recorded in the version's own follow-ups: the cold-clone check
belongs in the gate set before a version is tagged, not after.

## Deviations from the focused plan

| Planned | Delivered | Reason |
|---|---|---|
| Packaged Python project with a build backend and `src/lifegame/` | Virtual project (`package = false`), no library yet | The importable package is milestone M01; shipping an empty package to satisfy a build backend would have been content without a contract. Acceptance criterion A9 was reworded from "the package imports" to "the declared development dependencies resolve and the environment contract test passes". |
| `npm` temporary directory redirected through `npm_config_tmp` | Removed; `TEMP`/`TMP` carry it | npm 11 rejects the key (F4), and Node's `os.tmpdir()` reads `TEMP`. |
| pnpm store configured through `.npmrc` | Configured through `pnpm-workspace.yaml` | pnpm 10 moved these settings out of `.npmrc`; the `.npmrc` value had no effect (F5). |
| Two full snapshots around the workload | One timestamp-filtered scan after the workload | Created and modified files both carry a modification time at or after the workload start, so the second snapshot detected nothing extra while doubling the cost. The redesign took the isolation gate from 40.3 s to 14.8 s and back inside the 30 s limit. |
| Absolute cache paths in `uv.toml`, `.npmrc`, `pnpm-workspace.yaml` and `scripts/pip.ini` | Checkout-relative paths, and no settings at all in `.npmrc` | An absolute path names one checkout, so a clone or a git worktree wrote its caches into the original checkout (F8). Recorded as [../docs/adr/governance-and-build/0004-cache-locations-are-checkout-relative.md](../docs/adr/governance-and-build/0004-cache-locations-are-checkout-relative.md). |
| `prefer-frozen-lockfile` and `strict-peer-dependencies` declared in `.npmrc` | Removed | npm 11 reports both as unknown project configuration on every invocation; they are pnpm settings, and the defaults they were overriding are pnpm's own defaults. |
