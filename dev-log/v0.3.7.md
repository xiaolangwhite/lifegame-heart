# v0.3.7 — the timeline survives a switch, and the interface is finished

## Scope

Version `v0.3.7` delivers four requests and closes this phase's milestone 07:
the representation switch continues the recorded session (C12, T59); sessions are
capped at 64 with a bounded waiting queue; the remembered view point belongs to a
session and can be shared by link; a capabilities route names the seam a future
editing mode may use; undo of the last cell edit (C13, T60); controls that name
themselves and a hint line with the shortcuts (C14, T61); and saving and loading a
recorded world from the archives page (C15, T62). Version state is owned by
[../docs/plan/VERSIONS.md](../docs/plan/VERSIONS.md).

* a representation switch keeps the recorded session and the node count, then a
  further step appends to it;

## Results

**C12.** The core's `--continue-session ID` adopts a stored session instead of
creating one; the service asks the core which session it is recording before a
switch and hands it to the replacement. The recorded node count is unchanged by
the switch and the next step appends to the same session, which is the criterion
the phase table records.

**The queue.** The cap is 64 sessions including `main`; at most 1024 creations
wait. Beyond that the request is refused with `session_queue_full`, and the page
shows the waiting count. A shutting-down service answers waiters with
`service_closing` rather than leaving the requests open.

**Undo.** The page keeps the last 64 cell edits it made; undo toggles the most
recent cell back. The stack is emptied by any move this page did not make: a step,
a run, a clear, a placed pattern, a selection, a rollback, or a generation change.
A placed pattern and a clear are not in the stack, because the page cannot compute
their inverse without the prior state of the cells they touched; the recorded
timeline is the path for a bulk move.

**Save and load.** The archives page writes a recorded session with
`POST /api/archive` and loads one with `POST /api/archive/import`; the core's
`open` restores the world to the archive's newest generation. The service
resolves a name to a path inside one directory and forwards both commands; it
never replays a delta in JavaScript.

### C14 — the walkthrough

This is the written walkthrough the criterion asks for, performed against the
shipped service in a browser:

1. Open `/world`. Every control is visible with its label; hovering the undo,
   step, clear, pattern and new-session controls shows what each does, and the
   footer names the gestures and the keys, including `Ctrl+Z`.
2. Click a cell. The population readout rises by one, the generation does not
   change, and the undo control becomes available.
3. Press undo (or `Ctrl+Z`). The cell is gone and the population is back; the
   timeline has not moved, which is the difference from a rollback.
4. Click again, then press step (`.`). The generation advances and the undo
   control is disabled, because the world the edit was measured against is no
   longer the one on screen.
5. Choose a pattern and press place. The cells appear; undo is disabled for a
   bulk edit, as the page's documentation states.
6. Open `/archives`. Export the session to a name; the file is written inside the
   archive directory. Import it; the world returns at the saved generation with
   the saved population and the core opens it as a new session.
7. The session control in the footer lists `main` and any created sessions, with
   the waiting count when creations are queued.

## Failures

### F49 — the switch test created a second session

The first C12 case failed with `2 !== 1`: the same-session assertion read a new
store session. The cause was in the bridge, not in the core: `start()` rebuilt the
argument list without `continueSession`, so `--continue-session` never reached the
child. The option was added to that call and the case passed. Kept because it is
the one place where an option can be accepted by `restart` and dropped by
`start`.

### The isolation gate failed once, and was not reproduced

One `scripts/verify.ps1 -Full` run reported `1 of 12 gate(s) failed` at
`isolation (full, version-boundary)`. The standalone isolation run immediately
after reported `0 changed since the workload started, 0 excused, 0 unexplained`,
and the next `-Full` passed twelve of twelve. The failed run is kept: it is the
external-producer class the environment module's register describes, and a gate
that cannot be reproduced is not reported as passed.

## Deviations from the plan

| Planned | Delivered | Reason |
|---|---|---|
| Undo of the last edit | Cell edits only; a placed pattern and a clear are not undoable | The page cannot compute a bulk edit's inverse without the cells' prior state; the recorded timeline handles those, and the control says so (VWR-36) |
| An unbounded waiting queue behind the session cap | A bound of 1024, with `session_queue_full` beyond it | A queue that grows without a bound holds connections it cannot serve; the request said to refuse at the bound |
| A server-side shared view point for joint operations | The per-session point and the `?focus` link; the server-side store is left to the editing mode | The request placed real-time sharing inside the editing mode, which is still being planned |
| A separate world-file format for save/load | The recorded session archive, loaded back into the world | The store already owns a portable format and the core owns it; a second format would be a second implementation |
