# v0.3.2 — the interface as routed pages

## Scope

Version `v0.3.2` owns phase 03 milestone 02
([../docs/plan/phase-03-service-and-ui/milestones.md](../docs/plan/phase-03-service-and-ui/milestones.md)):
the world, the history and the archives stop sharing one document and get a path
each, the parts they share are declared once, and two defects that a person could
see but no test could are closed. Version state is owned by
[../docs/plan/VERSIONS.md](../docs/plan/VERSIONS.md).

## Why this version exists at all

The request that created this milestone named four things in one breath: a
duplicated heading, the archives sitting in the wrong place, a suggestion to split
the page into tabs "like browser tabs" with their own routes so it stops growing
into something unmaintainable, and a tree whose non-branch rows must not keep
indenting until they run off the edge.

The first three are one change: a page that has grown three concerns into one
document is the reason a second heading appears and the reason the archives are
wherever the history panel left room. The fourth is separate and is about
indentation.

## The route table, and what is declared once

| Page | Paths | Fragment | Module |
|---|---|---|---|
| world | `/`, `/world` | `public/pages/world.html` | `public/pages/world.js` |
| history | `/history` | `public/pages/history.html` | `public/pages/history.js` |
| archives | `/archives` | `public/pages/archives.html` | `public/pages/archives.js` |

`src/viewer/routes.mjs` is the only declaration of that table, and the service
asks it for a page rather than deciding for itself: a path it does not know
answers 404 instead of falling back to a default page. The shared layout —
document head, the theme script that runs before the first paint, the header, the
tab navigation, the footer and the script assembly — lives in one fragment with
slots, and **an unfilled slot throws** rather than quietly rendering a page
missing its navigation.

The shell went from 1923 lines to 626 because the timeline and the archive
management moved into the page modules that own them. Each page loads the shell
and its own module, in that order.

## What made the tests able to see the defect

This is the part worth recording, because the previous attempt at this split was
reverted after a person reported blank pages while the suite was green.

**A synthetic document cannot see a missing element.** The stub used by the
browser tests created an element the first time a script looked one up, so the
history page could lose the container its script binds and every test still
passed — and a real browser drew nothing, because the script returns early when
that container is absent. The stub now returns null for an id the markup does not
declare, and two contract tests assert both directions per page: every id a
route's script reads is declared by that route, and every id a fragment declares
is read by that route's module.

**A stylesheet is read, never evaluated.** The audit checked that a class the
stylesheet names appears somewhere in the file, so a renamed class left rules
behind that matched nothing and a person saw an unstyled panel while every test
passed. It now requires the class to appear where a class is *borne* — in a
`class=` attribute, a `className`, or a `classList` call — and separately that a
rule keyed on `data-panel` names a class the stage element actually carries.

Both were shown to bite by mutating the sources and restoring them: a deliberately
dead `.stage[data-panel='ghost'] .phantom` rule fails two cases, and deleting
`id="timeline"` from the history fragment fails nine, one of them by name.

## The history as nodes

A row is a button whose always-visible part is the generation and its branch
marker; the kind, the population, the change count and the time carry a detail
class that the stylesheet collapses and opens on `:hover` and on
`:focus-visible`. Keyboard focus is deliberate rather than incidental: a detail
that only a mouse can reach is a detail half the readers do not have.

Indentation is **fork depth**, not absolute depth: a level is added where a node
has more than one child and nowhere else, capped, and rebased on the shallowest
row currently shown so a windowed view is not a staircase. A linear run of twenty
generations is one column, which is the defect the request named.

## Failures

### F31 — the first attempt was reverted while it was green, and that was wrong

The split was attempted once before, reached a green suite, and was then reverted
when a report of blank pages arrived. The report was accurate about what a person
saw, but the two causes — a missing container and an unstyled panel — were
already understood and fixable, and the revert discarded work that had been
brought to green.

The record of why it happened is worth more than the work lost: the revert was
made while the writer was still active, from a gate run that raced with that
writer and failed for contention rather than for a defect. Those are two
independent mistakes, and either alone would have been recoverable.

What was done differently the second time: the redo was given both causes as
requirements rather than as context, the tests that can now see them were required
before the code was considered done, and the verification ran on a tree with no
writer on it.

### F32 — two gate failures that were contention, not defects

The full gate failed the viewer gate twice while a writer was active, and the same
suite passed every time it was run alone. A test suite that starts a service and a
core, run twice at once, contends for ports and for the history store. The lesson
is recorded rather than the incident: **do not run the gate while a writer is
working**, and when a gate fails, run the failing suite alone before believing it.
