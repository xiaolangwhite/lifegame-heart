# v0.3.4 — the preview opens on the current generation, and the probe becomes a tool

## Scope

Version `v0.3.4` owns phase 03 milestone 04
([../docs/plan/phase-03-service-and-ui/milestones.md](../docs/plan/phase-03-service-and-ui/milestones.md)):
two things the person who uses this interface asked for in one breath — the
preview should show something on arrival, and the instrument that found the
defects of the version before this one should stop being a one-off. Version state
is owned by [../docs/plan/VERSIONS.md](../docs/plan/VERSIONS.md).

## Why this version exists at all

The version before this one fixed four defects that only a browser could see, and
found them with a probe written by hand and left in a gitignored temporary
directory. That produced two follow-ups of very different kinds:

* the person using it decided the interface should preview the current generation
  on arrival rather than waiting to be clicked — a design change, and the version
  before this one had deliberately not made it;
* the instrument that found the four defects would not survive a clean checkout,
  so the interface was one commit away from being observable only by a person
  again.

Both are answered here: the first by changing the behaviour, the second by making
the probe a tool.

## The design change

`/history` now previews the current generation once it is ready. The conditions
are facts rather than timing: the page has not already previewed; nothing has been
placed; the canvas has been measured and the world is known; and the session has a
recording. It is tried again when a pane that had no size is given one, which is
what makes it work on a narrow window.

**The automatic preview does not select anything.** This is the load-bearing
part, and it is not a detail: `select` moves the working point as well as the
world, so an automatic preview that selected would record looking at a page as a
choice — and every later edit would branch from a generation the person never
chose. A test asserts that the automatic path sends no `select` and leaves the
working-point marker where it was.

The automatic path and the clicked path run through **one function**, so the
centring rule and the span rule cannot drift into two answers.

### F39 — the automatic preview could land on what the person had just chosen

Found by the implementer, not asked for. The automatic preview reads the live set
to find the cell nearest to the remembered view; if the person clicks a generation
while that read is in flight, the older answer arrives after the newer one and
would place the preview on the wrong generation. A placement whose read was
overtaken is now dropped.

The guard was shown to work by disabling it and watching the case fail
(`2 !== 1`), because an assertion that has never failed is an assertion nobody
has tested.

## The probe as a tool

`tools/browser-probe/` — fifteen files, 3954 lines, **zero npm dependencies**:
Node's built-in `WebSocket` and a browser binary already on the machine.

Three probes: **health** (every routed path 200 and an unknown path 404, with the
route list **read from `src/viewer/routes.mjs`** so the probe cannot drift from
the service), **geometry** (`getBoundingClientRect`, scroll widths, hit tests, and
an occlusion check that names the element on top), and **interaction** (real
presses and releases, the full event sequence, and every request the page issued —
which is what turns "the click did not select" into a red line).

Output is a machine report and a human report. The machine report is **pure ASCII
by construction**, with every non-ASCII character escaped, because the page's own
title is Chinese and PowerShell on this machine decodes files as ANSI, which
produces JSON that its own parser rejects.

**A gate that cannot run is reported as not run.** No browser means exit 2 and an
instruction, never a pass. `scripts/verify.ps1` gained a third state for this,
because a gate showing a tick it did not earn is worse than a known gap — and
this module has been burnt by exactly that.

### F40 — the tool leaked a browser process, and the leak was invisible

Worth recording because it is this repository's own historical failure mode
arriving in a new place. The first version left an Edge utility process behind:
it survived `taskkill /T /F` and **reported an empty command line** to the
process scan, so neither attribution path could see it.

Fixed with three changes, in order of reliability: ask the browser to close over
the protocol so its own shutdown reaps its children; attribute a second time after
killing; and treat the browser's profile directory as the last witness — if it
cannot be removed, something is still holding it, and the run says so loudly
rather than reporting success.

**The general lesson, and it applies to a defect of our own recorded below: a
process that hides its command line cannot be attributed by its command line. The
witness has to be the resource it holds.**

## A defect of ours this version found and did not fix

`scripts/viewer.ps1` refuses to start a second core while one from an earlier run
is alive, and it identifies those cores **by their command line**. In this
environment the command line is sometimes empty — observed twice now, once by
this version's implementer and once by the probe's author, independently.

The consequence is worse than a missing check: the guard fails **intermittently**,
which means it appears to work. A core it cannot see is a core it will happily
start a second writer beside, on the same history store.

The shape of the fix is now known from F40 — the witness should be the store
itself, which cannot be exclusively held twice — but it is not in this version,
and it is the first item of the next one. Recording it here rather than quietly
noticing it is the point: a guard that reports "nothing left behind" when it
cannot see is the same failure as a gate reporting a tick it did not earn.

## Failures

### F41 — the implementation corrupted two files and put them back

The implementer disabled a guard with a PowerShell read-and-write round trip to
check that a test could fail, and that round trip re-encoded a source file through
the machine's ANSI code page: invalid bytes, a byte-order mark, swallowed
characters. It restored the file from the commit and re-applied every edit,
then verified no mark, no carriage return, no invalid sequence, and read the diff
line by line.

It reported this itself, unprompted, which is why it is here. The maintainer
re-verified both files independently — no mark, no carriage return, no invalid
sequence, both parse — because this module has an older scar of exactly this kind
in `tests/viewport.test.mjs`, where a dash had been destroyed years earlier.

The lesson is the one the repository already knows and had not written down in
this place: **a text edit made through a shell round trip is not encoding-safe**,
and the only reason this cost nothing is that the file was under version control
and the author checked.
