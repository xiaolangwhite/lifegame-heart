# v0.3.6 — sessions, a pattern library and the storage choice

## Scope

Version `v0.3.6` is the sixth version of phase 03. It delivers the truncation
defect `STO-17` that `v0.3.5fix1` left open, and the three items this version was
introduced for: more than one session per service, a pattern library placed by
name from the interface, and automatic representation choice. Version state is
owned by [../docs/plan/VERSIONS.md](../docs/plan/VERSIONS.md).

## Results

**The truncation.** `Session.truncate_after` reads each surviving child of a
doomed node before anything is deleted, clears its parent link and rewrites it as
a keyframe of its own state, in the same transaction as the deletes and the head
update. The case builds the measured shape — nodes `[1,2,3,4,5]`, the head's path
`1 → 2 → 3 → 5`, node 4 a sibling under node 2 — and asserts that the survivor and
its child replay to the cells recorded on that branch, that the child stays a
delta, and that recording on top of the survivor still appends to it.

**Sessions.** `POST /api/sessions` starts a second core with its own history file
under `data/sessions/`; every session-scoped route takes `?session=`, omitted
means `main`, and an unknown id is `404 unknown_session`. The case creates a
second session, places a glider in `main` and a block in the other, asserts the two
populations, asserts that a step appends to the created session's history and not
to the default's, and closes the session. The default session is refused when
asked to close.

**Patterns.** `src/viewer/patterns.json` holds fifteen classic patterns in RLE;
one strict parser reads them; `POST /api/pattern` resolves a name against the
running world, checks the box, and sends one `set`. The suite asserts the
published population of every pattern, the parser's refusals, one-request
placement, a refused box sending nothing, and three behaviours through a real
core: a still life unchanged, a glider displaced by one cell in each axis, and the
gun growing from 36 to more than 36 in thirty generations.

**The storage choice.** `representation.mjs` carries the two measured anchors and
a density rule between them. After a placement the service exports the live set,
decides, and switches only when the choice differs and the population is at or
above 4,000. Two cases run against a real core: 4,096 packed cells placed into a
64 × 64 world switch it to `tiled` with the population preserved, and 4,000 cells
spread over an 8,192 × 8,192 world switch a tiled core back to `sparse`.

## Failures

### F48 — the first page case for a placement expected a pattern the select had not selected

The first red run of the new page case reported

```
AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:
+ actual - expected
+ undefined
- 'glider'
```

and there was no `/api/pattern` request at all. Two causes, both kept on the
record. The page looked the selected pattern up by the select's value, and the
synthetic document leaves a `<select>` with options and no value, so the lookup
returned `undefined` and the function returned early — a click that looks pressed
and does nothing, which is the shape VWR-28 had. The page now chooses the first
pattern when the document leaves the select empty. The case itself also never
selected the glider before pressing; it does now.

### The file-permission denial

Kept because it was a failed run of a gate command, not because it is a product
defect: the first `pytest` of this version aborted with
`PermissionError: [WinError 5]` on `TEMP\pytest-of-20112` before collecting a
single case. The repair and its evidence are described under Environment.

## Deviations from the plan

| Planned | Delivered | Reason |
|---|---|---|
| Complete M03 including C12, "a representation switch does not truncate the timeline" | C10 and C11 are judged; C12 is **not**, and it is owned by v0.3.7 as task `T59` | A switch replaces the core process, and the new core opens the same store but starts a new recorded session. Continuing it needs a decision about a core that adopts an existing session, which is a change to the core and the protocol rather than to the service |
| The automatic storage choice presented as a measured rule | The two anchors are measured; the density boundary (0.05) is chosen between them | Nothing has stepped the band between the packed and the spread shapes, so the boundary is a decision with a test at it, recorded as VWR-32 |
| Sessions presented as durable | The registry is in memory; closing a session stops its core and leaves its history file | Persisting the registry means reconciling service ids with the store's own session ids, which is a design of its own (VWR-30) |
| A default archive name `archive.jsonl` for every session | `archive-<session>.jsonl` for a created session | Two sessions exporting under one name would overwrite each other's file |
