# v0.3.5 — a rule editor, and a world that accepts what it is given

## Scope

Version `v0.3.5` owns phase 03 milestone 05
([../docs/plan/phase-03-service-and-ui/milestones.md](../docs/plan/phase-03-service-and-ui/milestones.md)):
a rule editor on the main page in the general `BxxSxx` form, with both presets and
free entry, and a world that accepts what it is given — core, protocol, recorded
history and interface in one version. Version state is owned by
[../docs/plan/VERSIONS.md](../docs/plan/VERSIONS.md).

## Why this was not a control

The request reads as an interface addition. It was a change to the simulation, and
the reason is worth keeping: the tiled representation did not evaluate Conway's
rule, it *was* Conway's rule, folded into bit operations —
`next = ~s3 & ~s2 & s1 & (alive | s0)`. Given another pair of sets that expression
is not slow, it is wrong. So the work ran along a chain where each link depends on
the one below:

1. the core carries a rule rather than an assumption;
2. the protocol carries it, so the interface can set it and read it back;
3. the recorded history replays each generation under the rule that generated it;
4. and only then does the interface get its input.

## The algorithm

Counting is separated from deciding.

* **Count**: the eight neighbour bit-planes are summed position-wise into four
  planes holding 0..8 through the existing full-adder chain — 8 neighbours × 4
  ripple levels = 32 full adders = 64 word operations per tile, unchanged from
  before this version.
* **Decide**: each set is packed into a sixteen-bit mask whose bit *i* says
  whether *i* is in the set. The counts 0..7 are split into four groups by their
  2s and 4s places, one AND selects a group, and at most one more operation
  selects its even member, its odd member or neither. The count of eight is the 8s
  plane alone, folded in with one OR — or guarded out with one AND when the set
  names zero but not eight. Birth and survival share every operand they have in
  common through a memoised expression.
* **Apply**: `next = (alive & survive) | (~alive & born)`.

**The default rule pays nothing.** Conway compiles to three operations
(`p1 & ~p2`, `p1 & ~p2 & p0`), against the seven of the expression it replaced, so
the generality is free for the rule everybody uses. There is no
`if rule == CONWAY` anywhere; the specialised expression falls out of the
compiler, and a case asserts it does.

**Two bounds, and a correction.** The bound *per set* is sixteen, exhaustively
checked over all 512 single sets. The bound *per rule* is larger, and an earlier
revision of this version claimed sixteen for it too, saying all 262144
`(birth, survive)` pairs had been compiled and none exceeded sixteen. **That claim
was never measured and is false**: the measured worst case is **twenty-four**
(`B13578/S0246`) and 124240 pairs exceed sixteen. The docstring now states the
measured truth, and a case compiles all 262144 pairs and asserts twenty-four, so
the number cannot rot again. It was found by a documentation pass that measured
instead of copying.

## Cost, measured

Method: **three interleaved rounds** of one warm-up plus five timed runs. Order
matters — measured sequentially, whichever path is measured first is faster by
more than the true difference between them.

| Whole step, lattice 1024², 200k live | plan | ms | against the old expression |
|---|---|---|---|
| Conway, compiled | 3 | 2.040 | 1.01× (inside the noise) |
| Conway, the expression it replaced | 7 | 2.024 | 1.00× |
| `B36/S23` HighLife | 7 | 2.394 | 1.17× |
| `B3/S12345` Maze | 9 | 2.440 | 1.20× |

Measured on the rule application alone (256 tiles), the heaviest preset —
`B3/S012345678`, an eleven-operation plan — costs 11.67× the specialised
expression. **Where that goes is stated rather than blurred**: each plan word is a
pass over an `(M, 64)` array, plus the Python cost of walking the plan (about
17 µs per call at 256 tiles). The whole step grows only 17–20 % because the
geometry — eight gathers and the 64-operation adder chain — is independent of the
rule and dominates.

The frontier recorded when the tiled representation was introduced was re-measured
and lies inside the run-to-run band already on record, with one exception:
`sparse` at 200k is about 16 % off its record, and its hot path is byte-for-byte
unchanged, so that rung is machine noise — judge `sparse` at the 260k rung, and do
not quote the 40k rung, which carries ±18 %.

**Not adopted, and named as unmeasured:** a carry-save (3:2) tree would cut the
adder chain from 64 word operations to about 34, which is now the bulk of a step.
It was left alone because adopting it would change the frontier this version is
being compared against, and because it needs its own correctness proof. It is
recorded as a candidate, not as a result.

## The find that mattered most: `B0` is not a local rule

The cross-representation equivalence test — fourteen rules, three
representations, a dense oracle as judge — caught a defect that predated this
version. A rule with `0` in its birth set means **every dead cell with no live
neighbours is born**, which is every dead cell in the world; at the design scale
of 4.29e9 cells neither of the two local representations can carry it. Measured:
an 8×8 world with one live cell under `B012345678/S` gives **63 live cells
correctly and 39 from `sparse`** — a wrong answer, silently.

`sparse` and `tiled` now refuse such a rule with a `ValueError`; `dense` still
runs it, as the oracle and the way out. **This is the version's only outward
behaviour change**, and it is a change from a silent wrong value to an exception,
which is the right direction: a simulator that is wrong without saying so is the
worst failure mode there is.

## The protocol

`set_rule` was added, taking a rule and returning it normalised with both lists:

```
{"id":N,"cmd":"set_rule","rule":"b36/s32"}
  -> {"ok":true,"id":N,"rule":"B36/S23","birth":[3,6],"survival":[2,3]}
  -> {"ok":false,"id":N,"error":"bad_rule","message":"<readable reason>"}
```

It changes the rule and nothing else: no cells, no generation counter — it is
neither an edit nor an undo. `hello`, `state` and `export` carry the rule;
`history` carries each node's own; `import` accepts one; `open` adopts the
archive's. The command count is **eighteen**, not the sixteen the documents had
claimed since before this version — `select` and `open` had never been listed, and
that was found only because a documentation pass counted the handlers in the code
instead of trusting the table.

## The recorded history

Schema 2 → 3. Every generation row carries the rule in force at that node, and a
session carries `rule_known`, which distinguishes a rule that was **stated** from
one that was **assumed** because an archive named none. `Session.rule_changes()`
returns the points where the timeline's rule changed.

The design choice was between storing the rule per row and storing it only where
it changes. Inheritance was rejected on measurement, not on taste: every
single-node read would have had to walk to the nearest ancestor that states a
rule, and `record` reads the head once per generation while `path_to` runs per
rollback and select — so in the common case, where the rule never changes, it
walks to the root, which is quadratic in the length of a session. Per-row reads
are constant and are also immune to a later `set_rule` retroactively relabelling
generations that were generated under another rule. The cost is measured: 256×256,
2001 generations of a glider — the rule column is 12 006 bytes, **6.0 bytes per
generation**, against 16.5 for the born-and-died payload, 26.6 % of a row in the
worst case of very small deltas and under 3 % with larger ones.

Migration 1 → 3 and 2 → 3 are read-rebuild-write through one writer. **Old
sessions get their session rule written onto every generation**, because schema 2
kept exactly one rule per session and that is the only evidence there is; for a
session that never changed its rule that is exact, and for one that did, the
change point is **not recoverable** — the generations after it are labelled with
the rule the session started under. That uncertainty is written into the migration
itself rather than left for a reader to discover.

Archives carry the rule in the header and on every line, so a line read alone can
answer what ran there. The archive version stays 1 because both fields are
additive. A file that names no rule imports on the default, records
`rule_known = 0`, and keeps saying so when re-exported, so a guess cannot become a
fact by passing through a newer build.

The `bridge` had kept a **copy** of the rule for `hello`, `state` and `export`,
with a constructor parameter to set it. Nothing passed that parameter, so it was a
trap rather than a bug: a `Bridge` built over a world on another rule would have
reported the default. The copy and the parameter are gone and those three read the
world's own rule.

## The interface

The main page's control row ends with the rule editor: a preset select, a text
field, and a button. Presets are Conway, HighLife, Maze, Seeds, `B/S012345678`,
Day & Night, Replicator and Life without Death; the words live in the locale
table in both languages.

The client validates first and sends nothing for a malformed rule, saying in
words which part is wrong; the core remains the authority, and a `bad_rule`
answer is shown with the core's own reason while **the rule is not changed** — the
readout, the select and the world keep describing what is actually running, and
the field keeps what was typed so it can be corrected.

When the core reports a rule that is not one of the presets, the select shows a
ninth entry reading `custom · <the rule>`. The alternative — snapping to the
nearest preset — would have a control claiming a rule the core is not running;
carrying the rule's own text makes the control honest and still says what is in
force. Choosing that entry sends nothing, because "custom" is not a rule; it moves
the focus to the field instead.

The history page states the difference when the generation being looked at ran
under another rule — "generation N ran X; the current rule is Y" — and offers one
press to adopt X. **Nothing else changes the rule**: not selecting, not stepping,
not dragging, not the automatic preview. Each of those is asserted individually,
because "adopt the rule" quietly becoming "adopt it whenever you look at
something" is exactly the kind of drift that reads as a feature.

## Failures

### F42 — the rule editor's button did nothing on a fresh page

Found by the browser probe, after the suite had been green at 337 cases.

The shell publishes its context **before** it awaits its state, so the page module
starts while `state.rule` is still empty. The field was filled only during
start-up, and only when a rule was already known — so on a real first load the
readout and the select correctly showed `B3/S23` while the field was empty, and
pressing the button submitted an empty string, which was refused locally in words.
**The feature was unusable the first time anybody used it.**

Fixed by filling the field the first time a rule arrives, and never again once the
person has typed in it — a field that rewrites itself under a typist is worse than
an empty one. A case now reproduces the real order with a handshake the case
releases itself, asserts the field was empty before, that it opens on the rule
after, and that the button then sends that rule. The synthetic document could not
have caught this: it fed the handshake in an order that filled the field, which is
the third time this module has been wrong only in a browser.

### F43 — a representation switch dropped the rule

Found by the store's implementer while working in another module, and reported
rather than quietly fixed. The service exported the world, restarted the core on
the other representation and imported it back — **without the rule**. So switching
representations returned a session to Conway, and an export taken afterwards
carried the wrong rule: the session had quietly changed its own meaning.

Fixed in the service, which now sends the rule back exactly as it came out and
omits it when an older core does not report one. The end-to-end case sets a rule
that is **not** the default before switching: with the default, a dropped rule
would have fallen back to the same value and the assertion would have passed for
the wrong reason.

### F44 — the isolation gate counted other programs' writes

The full gate failed a check for a reason unrelated to this version: the dynamic
isolation phase counts anything written to the system temporary directory during
its window, and the machine's own browser and remote-desktop client write there
continuously. Nothing of the repository's was involved, and running that gate
alone reproduced the failures.

The gate now admits three **named** producers — the machine's zero-length GUID
temporaries, the browser's own scratch files, and the remote-desktop client's
traces — and the code says why each is not ours. It is a list of named producers,
not an amnesty: a run still reports that it saw changes and that none were ours.
The browser class had to be widened once, from the update log to the pair of
names, after an `edg<n>.tmp` failed the gate twice on an unchanged tree.

### F45 — documents describing an implementation that no longer exists

This version's documentation passes kept finding them, and they are recorded
because each was a claim a reader would have trusted:

* the store contract still described **schema 1** and asserted that **no
  migration was implemented**, two versions after both stopped being true, and had
  never been synced to schema 2 either;
* the protocol table listed **sixteen** commands and had **never** listed `select`
  or `open`, which had been in the code since the tree was built;
* the history section still said that stepping on from a loaded generation
  **discards** the recorded future — false since the tree, where `rollback` only
  reads and `select` moves the working point while keeping the children;
* the `bridge` module docstring, which the interfaces document names as the
  authority for the protocol, listed seventeen commands and repeated the
  three-command reading of `--history`;
* a component document showed a `Bridge` constructor parameter that had just been
  deleted as a trap.

## Deviations from the plan

| Planned | Delivered | Reason |
|---|---|---|
| The version was described as a rule editor | The core, the protocol, the store and the interface in one version | The interface cannot set a rule the core cannot carry, and the core cannot be trusted to carry one the history cannot replay. |
| The `≤16` word-operation bound was relayed as applying to every rule | Corrected to a per-set bound of 16 with a measured per-rule worst case of 24 | The number had been claimed and never measured. It is now asserted by a case that compiles all 262144 pairs. |
| `select` and `rollback` would adopt the rule of the generation they load | They do not; the history page states the difference and offers one press | The person who uses it chose this. A preview that silently changes the rule is a change made on their behalf; a statement plus a button is not. |
