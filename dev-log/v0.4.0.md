# v0.4.0 — the single-machine editing mode

## Scope

Version `v0.4.0` delivers phase-04 milestone M00: the core's atomic `patch`, the
editing document with its version and hash chain, the editing runtime and its
routes, the page's editing tools, and the content-addressed snippet library with
drafts and publish. The phase's later milestones — collaboration, roles and
operation-log persistence — are not part of this version. Version state is owned
by [../docs/plan/VERSIONS.md](../docs/plan/VERSIONS.md).

## Results

**The core's `patch`.** The command validates both lists, the cross-list duplicate
rule and `expectGeneration` before writing anything, applies born then died in one
pass, and records one edit. It answers with `born` and `died` arrays naming the
cells that actually changed, so the service records the change that happened
rather than the candidate it sent.

**The document.** `edit.mjs` validates a transaction into absolute intents, keeps
the version and chain hash, rebases a stale base when every operation is absolute,
refuses a content-dependent stale base, and records inverse-transaction undo
restricted to the cells the undone transaction still owns.

**The runtime.** `edit-runtime.mjs` pauses a running world on enter and resumes it
on leave, sends the candidate cells to `patch`, records the returned change,
broadcasts a `patch` event, invalidates the frame stream, and answers undo, redo
and the resync window. The server refuses every other world-writing route with
`edit_active` while the mode is open.

**The snippet library.** One immutable object per content hash, a versioned
`index.json`, compare-and-swap publish with a pinned hash, the name rules and the
256 x 256 / 8192 limits. Removing a name removes the index entry and keeps the
object. The four routes are published in `/api/snippets`.

**The page.** An explicit edit control opens the toolbar; paint, erase, line and
rectangle are one transaction per gesture; select defines a selection that can be
saved as a browser-storage draft and published; stamp places the selected snippet
with a transform and `overwrite` or `merge`; undo and redo call the session's
routes, and a stale refusal resyncs and says so.

## Failures

### F50 — the page suite's teardown started a world while editing

The first run of the new page cases left a `ReferenceError: window is not defined`
after some tests. The teardown stopped a run loop by clicking the run button
whenever the step button was disabled; in the editing mode the step is disabled
because the world is paused, so the teardown started a run the test never asked
for, and its polling outlived the restored globals. The teardown now checks
whether the run button itself is disabled (the editing mode) and only then skips
the click. Recorded because it was a test-harness defect, not a page defect.

### F51 — the import contract did not know `edit-tools.mjs`

The page suite's import check refuses an unlisted module so an import cannot
silently stop being checked. The first full run failed with
`pages/world.js imports ../edit-tools.mjs, which the contract check does not know
about`; the module was added to the check's map.

## Deviations from the plan

| Planned | Delivered | Reason |
|---|---|---|
| The service reads the region and computes born/died | The service sends candidate cells; the core filters no-ops and answers with the actual change | Keeps the world model in the core, keeps undo attribution exact, and avoids a read-then-write race; recorded in ADR 0012 |
| A selection is published straight from the service | A selection becomes a browser-storage draft; publish is a separate press | The request asked for local drafts plus a publish step (Q8c), and an unpublished experiment should not enter the shared palette |
| The stamp operation resolves its source in the service | The page resolves a snippet through `/api/snippets` and sends a `fill` with relative cells | The service has no second copy of the snippet content, and the route is the same one the page already reads; the service still validates the box and the limits |
| A line tool with a preview | The line is committed on pointer-up; the preview is a single dashed segment | A live per-cell preview is a canvas feature, not a transaction feature, and it is not needed for the criteria |
