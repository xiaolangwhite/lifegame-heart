# Phase 01 — risks

> Every unresolved risk names the version that owns it. A risk without an
> owning version is a defect
> ([../../AI_DOCUMENTATION_GUIDE.md](../../AI_DOCUMENTATION_GUIDE.md) §5.8).

| Id | Risk | Trigger | Impact | Mitigation | Owning version |
|---|---|---|---|---|---|
| R01 | A directory created outside a sandboxed session does not inherit the low-integrity label that sandboxed sessions require, so sandboxed writes to it fail. | A folder is created in the project by an unsandboxed process, or a folder is created while no sandbox label policy is active. | A confined agent session cannot write into that folder at all; directory creation succeeds for the user and fails silently for the agent. | Keep every project directory creation inside `scripts/bootstrap.ps1`, which runs in the same session context as the work; verify writability in `scripts/verify-temp-isolation.ps1`. | see [../VERSIONS.md](../VERSIONS.md) |
| R02 | An unsigned PowerShell script is blocked by the machine execution policy, and a blocked `env.ps1` silently looks like a successful run. | A session forgets `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`. | The uv cache and interpreter payload fall back to the system volume, violating the isolation contract without an error at the point of use. | The gate refuses to continue when a transient location points at `C:`; the isolation check fails loudly; the required preamble is documented in [AGENTS.md](../../../AGENTS.md) §1. | see [../VERSIONS.md](../VERSIONS.md) |
| R03 | Node package managers resolve their store on the system volume when a project-level config is missing. | `pnpm install` runs outside the project root. | Cache and store land on the system volume. | The project config is committed; the isolation check inspects the resolved store location. | see [../VERSIONS.md](../VERSIONS.md) |
| R04 | uv resolves the relative `cache-dir` declared in `uv.toml` against the current working directory, while pnpm resolves a relative `storeDir` against the workspace root. | A uv command is run from a subdirectory instead of the repository root. | A second uv cache tree appears under that subdirectory. It stays inside the checkout — never on the system volume and never in another checkout — but the location is not the declared one. | [AGENTS.md](../../../AGENTS.md) §1 fixes the working directory at the repository root; `UV_CACHE_DIR` from `scripts/env.ps1` overrides the declaration entirely; the isolation check asserts the resolved location from the root. | see [../VERSIONS.md](../VERSIONS.md) |
| R05 | The conformance gate can be weakened to make a change pass. | A check is relaxed instead of the document being fixed. | The gate stops being evidence. | Check codes are fixed in [../../../tools/documentation/README.md](../../../tools/documentation/README.md); removing or renaming a code is a decision that requires an ADR, and the gate's own tests assert the codes. | see [../VERSIONS.md](../VERSIONS.md) |
| R06 | A tool that is not covered by the environment contract writes to the system volume. | A new tool is added without updating the contract. | Silent violation of the isolation requirement. | [AGENTS.md](../../../AGENTS.md) §1 requires updating `scripts/env.ps1` and the module's `interfaces.md` in the same change. | see [../VERSIONS.md](../VERSIONS.md) |
| R07 | The two package manifests carry different versions, and neither is the project's: [pyproject.toml](../../../pyproject.toml) declares `0.2.1` and [package.json](../../../package.json) declares `0.1.0` | A reader or a tooling step treats a manifest version as the project version | A second and a third place that states a version, disagreeing with each other and with [../VERSIONS.md](../VERSIONS.md); whichever is read first becomes the one believed. Neither artifact is published today, which is why the disagreement is quiet | Neither version is consumed by a released artifact: the Python package is built from the checkout and the Node package is private. The decision needed is whether the three-component version propagates into them at all; [DOCUMENTATION_RULES.md](../../DOCUMENTATION_RULES.md) §6 says only that the fourth component does not | the version naming phase 01 milestone 01 in [../VERSIONS.md](../VERSIONS.md), where the package and service skeletons are delivered |
