# Phase 02 — risks

> Every unresolved risk names the version that owns it. A risk without an
> owning version is a defect
> ([../../AI_DOCUMENTATION_GUIDE.md](../../AI_DOCUMENTATION_GUIDE.md) §5.8).

| Id | Risk | Trigger | Impact | Mitigation | Owning version |
|---|---|---|---|---|---|
| R10 | **Closed for clustered populations by the milestone 01 version.** The shipped sparse representation loses to the dense reference above roughly four percent density, and the design target admits far higher densities: one percent of 65536 x 65536 is 43 million live cells, which the sort-based step would need about nineteen seconds per generation to advance. | A pattern grows past the measured crossover, or a dense viewport is populated. | Was: the target-scale world can be represented and edited but not run at interactive speed. | The tiled bit-parallel representation shipped in [milestones.md](milestones.md) M01, measured on two population shapes: it wins from about 4,000 live cells when the population is clustered, by a factor of 55 at 260,000, and the target-scale projection falls to about 89 ms per generation. Recorded in [ADR 0010](../../adr/simulation-core/0010-tiled-bit-parallel-representation.md). | closed for the clustered shape; see R16 for what replaced it |
| R16 | Nothing chooses between the two representations. The default is `sparse`, which is right for cells placed by hand and wrong for a clustered pattern, whose step is then fifty times slower than it needs to be. Querying pulls the other way, so the choice is not obvious from one number. | A clustered pattern is run without passing `--representation tiled`. | A large clustered pattern runs on the slower representation and the user has no way to know except by reading the measurement. | The frontier measurement in [../../plan/PERFORMANCE_ACCEPTANCE.md](../../plan/PERFORMANCE_ACCEPTANCE.md) §5.2 is the input a selection rule needs. The rule itself moved out of this phase when the version naming M02 shipped the *manual* switch without it: the service already knows the population and already knows how to switch storage losslessly, so the choice belongs there, and [../phase-03-service-and-ui/milestones.md](../phase-03-service-and-ui/milestones.md) M01 owns it. | the version naming phase 03 milestone 01, see [../VERSIONS.md](../VERSIONS.md) |
| R11 | numpy is a compiled dependency, so native code sits in the runtime path. | A platform without a numpy wheel for the interpreter, or a policy decision to keep the runtime pure Python. | The core cannot run, or the dependency decision has to be revisited under pressure. | [ADR 0006](../../adr/simulation-core/0006-numpy-is-the-vectorised-substrate.md) records the native boundary, the build integration and the portable fallback; the dense oracle and the benchmark's dictionary implementation show what a pure-Python path costs. | see [../VERSIONS.md](../VERSIONS.md) |
| R12 | The viewer polls for frames, so a running world is bounded by round-trip latency and by frame size; a dense 1024 x 1024 viewport is about 171 KB per frame in base64. | A large viewport is rendered while the world runs, or the tick rate is raised. | The browser falls behind the world, and requests queue up. | The page never issues a new frame request while one is outstanding; the push transport is scheduled in [milestones.md](milestones.md) M01. | see [../VERSIONS.md](../VERSIONS.md) |
| R13 | The browser surface has no automated test; only the HTTP API below it does. | A rendering, coordinate-mapping or zoom defect that the API tests cannot see. | A visible defect ships with a green suite. | The coordinate mapping is kept in one small function with the HTTP contract around it; automating the browser is scheduled in [tasks.md](tasks.md) T44. | see [../VERSIONS.md](../VERSIONS.md) |
| R14 | The line protocol has exactly one implementation and no compatibility test against an older consumer. | The protocol changes while a viewer build is in use. | The two sides disagree and the failure mode is a hang rather than an error. | The protocol version is carried in `hello`; the bridge answers every malformed request with a named error instead of dying. A compatibility fixture is scheduled with the push transport. | see [../VERSIONS.md](../VERSIONS.md) |
| R15 | The world is bounded and does not wrap, which is a decision, not a default; a user may expect a torus and read edge behaviour as a bug. | A pattern reaches an edge. | Patterns at edges decay where a torus would let them continue. | The condition is recorded in [ADR 0008](../../adr/simulation-core/0008-the-world-is-bounded-and-does-not-wrap.md), tested in `tests/world/test_patterns.py`, and stated in the module's `interfaces.md`. | recorded; no change planned |
